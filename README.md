# AORI INTEL V2.1｜アオリイカ釣果情報

越前〜丹後の岸・船・定置網情報を別々に扱うスマホ向けWebアプリ。

## 設計原則
- 計測できていない地域・時刻は「釣れない」ではなく「材料不足」とする
- HIT数は釣果数ではない。同じ投稿IDの使い回しを重複計上しない
- 投稿時間と釣行時間を混同しないため、確かな実釣時間のないCPUEは表示しない
- 船中合計・一人最多・一人の釣果範囲を分けて表示する
- 複数魚種にまたがる曖昧な数値は取り込まない
- 元記事を確認できない検索スニペットは「確定釣果」にしない
- 固定情報源とRSS広域探索、検索API任意接続を組み合わせる
- 定置網は岸の杯数に換算しない。水温海況は別データ（未実装の時は空表示）

## 収集
`.github/workflows/collect.yml` はUTC 3時間間隔で起動要求する。GitHub側の遅延があるため実際の間隔は保証されない。

`source-status.json` の `new_count` は既存と照合した新規の件数、`parsed_count` は今回ページから取得した既存を含む件数。エギCOMでは新規イベントIDの数を報告する。

`discovery-status.json` は広域検索成功数・失敗数・候補・新規採用を区別。Braveキー未設定ならBing RSSの公開検索を各地域で試行する。サイト側で拒否された場合はエラーを表示し、成功扱いにしない。

## バージョン管理と回帰テスト
- `npm run validate`（構文＋解析回帰テスト）
- `npm run collect`（公開固定情報源の試行）
- `npm run discover`（Brave API またはRSS検索の試行）

データは過去30日分とユーザー記録を保持し、継続的にソース識別子で統合。GitHub Actions と Pages の成功は情報の真偽を保証しない。リリース時に実取得データの品質を確認する。
