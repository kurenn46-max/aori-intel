# AORI INTEL V2.3｜アオリイカ釣果情報

越前〜丹後のアオリイカ実釣情報を岸・船に分けて一覧するスマホ向けWebアプリ。定置網はアオリ入網が裏付けられた記録だけ補助表示。

## 設計原則
- 計測できていない地域・時刻は「釣れない」ではなく「材料不足」とする
- HIT数は釣果数ではない。同じ投稿IDの使い回しを重複計上しない
- 投稿時間と釣行時間を混同しないため、確かな実釣時間のないCPUEは表示しない
- 船中合計・一人最多・一人の釣果範囲を分けて表示する
- 複数魚種にまたがる曖昧な数値は取り込まない
- 元記事を確認できない検索スニペットは「確定釣果」にしない
- 固定情報源とRSS広域探索、検索API任意接続を組み合わせる
- 定置網は岸の杯数に換算しない。水温海況は別データ（未実装の時は空表示）

## 収集
`.github/workflows/collect.yml` はUTC 3時間間隔で起動要求する。GitHub側の遅延があるため実際の間隔は保証されない。

`source-status.json` の `new_count` は既存と照合した新規の件数、`parsed_count` は今回ページから取得した既存を含む件数。エギCOMでは新規イベントIDの数を報告する。

`discovery-status.json` は広域検索成功数・失敗数・候補・新規採用を区別。Braveキー未設定ならBing RSSの公開検索を各地域で試行する。サイト側で拒否された場合はエラーを表示し、成功扱いにしない。

## バージョン管理と回帰テスト
- `npm run validate`（構文＋解析回帰テスト）
- `npm run collect`（公開固定情報源の試行）
- `npm run discover`（Brave API またはRSS検索の試行）

データは過去30日分とユーザー記録を保持し、継続的にソース識別子で統合。GitHub Actions と Pages の成功は情報の真偽を保証しない。リリース時に実取得データの品質を確認する。

## 検索語ローテーション V2.2
- 毎回8地域を必ず検索。漁港名・釣り方・季節語の組み合わせを巡回ごとに変更する
- 直近7日の岸釣果情報が少ない地域に追加の検索4枠を割り当てる（報告が少ない＝釣れていない、ではない）
- data/search-rotation.json へ次の巡回番号、前回の検索語、語ごとの結果数を保存する
- 無関係な記事ばかりの場合は search_irrelevant と判定し、成功とは表示しない
- 検索語の変化だけでは検索サイトの品質問題は解決しない。固定情報源を中心とし、元記事で確認できない釣果は確定データにしない

## V2.3 アオリ釣果特化
- 主要な画面は岸釣果・船釣果の2種類のみ。検索や情報評価の主対象はアオリイカの実釣レポート
- 実際の捕獲イベントと投稿日時を区別し、確認釣行数、1人最多、3杯以上の釣行、最新釣行日を表示
- 定置網情報の収集自体は維持する。ただし、入網魚種としてアオリイカが明記され、定置網に帰属するものだけを折り畳みの参考欄に表示する
- 魚種の特定できない定置網水揚げやベイト魚はアオリ釣果の数字に含めない
- 複数地域・岸船を合算してイカが多いと断定しない。材料不足ならその旨を表示する

## V2.3.1 更新操作の明確化
- 「更新確認」は公開済みデータを再取得し、新しく追加された記録があれば表示する。操作時に収集プログラムは走らない
- ネットワーク取得が失敗したときは元データを消さずにエラーを表示する
- GitHub Pagesでは匿名クライアントからActionsを安全に起動できないため、手動収集はログイン後のGitHub Actions画面から Run workflow を押す。アクセストークンをWebのJavaScriptに埋め込まない
- 収集は引き続きGitHub Actionsの定期処理で実行され、情報がなければ画面は変わらない
